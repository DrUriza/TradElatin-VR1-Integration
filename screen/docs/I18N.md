# TradELATIN VR1 i18n architecture

TradELATIN uses **one Dash process, one port and one explicit language state**.

## Single source of truth

The only authoritative language state is the URL query:

- `?lang=en`
- `?lang=es`

No cookie, localStorage, DOM translator, MutationObserver, secondary locale store, or language environment variable participates in language selection.

```text
EN / ES button
      |
      v
  url.search
      |
      +--> global shell
      +--> page renderer
      +--> family callbacks / figures
```

Only the EN/ES button callback writes `url.search`. Every renderer consumes it. Nothing writes back to the language state, so there is no i18n feedback loop.

## Why this is easy to debug

If a string is in the wrong language, inspect the URL first:

```text
/prices/analysis?lang=en
/prices/analysis?lang=es
```

If the URL is correct, the bug is local and deterministic:

1. a visible source string is not in the translation dictionary; or
2. a callback returning visible content is not consuming `url.search` / applying the resolved locale.

Enable optional tracing:

```powershell
$env:TRADELATIN_TRACE_I18N="1"
.un.ps1
```

Example:

```text
[I18N] event=shell locale=es pathname=- search=?lang=es
[I18N] event=render locale=es pathname=/prices/analysis search=?lang=es
```

The trace flag does not select the locale; it only prints diagnostics.

## Source-string policy

Visible HMI source strings are canonical English. Spanish is produced only by `screen_core/i18n.py`. Technical identifiers such as CVD, OI, ETF, VWAP, RSI, DVOL, Spot/Futures, HMI and Wasserstein remain canonical where appropriate.

This makes missing translations easy to locate: search the English source string and add one explicit EN -> ES entry.

## Contextual help

Contextual help is presentation-only and remains outside financial contracts:

- `data/help/contextual_help_vr1_en.json`
- `data/help/contextual_help_vr1_es.json`

Both registries have the same **144 semantic IDs**. Popup timing, positioning and structure are shared; only the localized content changes.

## Financial contracts

`data/contracts/*.json` remains language-neutral. Processing continues to produce one canonical contract per family.
